# 10: Config suppressions

**What to build:** Adopting teams excuse known findings from config with a documented reason and expiry.

**Blocked by:** 06 (Scores, gate checks, enforcement and score --report)

**Status:** resolved

- [x] Suppressions match on rule glob and path glob and mark findings `suppressed` with the reason in the status note
- [x] Expired suppressions are ignored and listed as warnings
- [x] Suppressed findings never change scores or gate checks

## Demo

Build the binary once from the repo root: `go build -o /tmp/qgate ./cmd/qgate`. Then paste the script below (it needs `git` and `jq`). A change builds SQL by concatenation in two places: generated code under `gen/` and hand-written `app.go`. A blocking gate allows no new high findings.

```bash
# 1. A change that trips two rules, and a gate that blocks on high findings
rm -rf /tmp/qgate-demo-10 && mkdir /tmp/qgate-demo-10 && cd /tmp/qgate-demo-10
git init -q -b main && git config user.email demo@example.com && git config user.name Demo
mkdir gen && printf 'package gen\n' > gen/queries.go && printf 'package app\n' > app.go
git add . && git commit -qm base && BASE=$(git rev-parse HEAD)
printf 'package gen\n\nvar q = "SELECT " + col\n' > gen/queries.go
printf 'package app\n\nvar q = "SELECT " + col\n' > app.go
git add . && git commit -qm "build queries"
cat > semgrep.sarif <<'EOF'
{"version":"2.1.0","runs":[{"tool":{"driver":{"name":"Semgrep","rules":[{"id":"sql-concat"}]}},"results":[
 {"ruleId":"sql-concat","level":"error","message":{"text":"SQL built by concatenation"},"locations":[{"physicalLocation":{"artifactLocation":{"uri":"gen/queries.go"},"region":{"startLine":3}}}]},
 {"ruleId":"sql-concat","level":"error","message":{"text":"SQL built by concatenation"},"locations":[{"physicalLocation":{"artifactLocation":{"uri":"app.go"},"region":{"startLine":3}}}]}]}]}
EOF
cat > .qgate.yaml <<'EOF'
version: 1
inputs:
  - { name: semgrep, format: sarif, path: semgrep.sarif, category_default: security }
profiles:
  dev: { enforcement: blocking, gate: { max_new: { high: 0 } } }
EOF

# 2. Without suppressions the gate fails on two high findings
echo "== 2"; /tmp/qgate run --base $BASE | head -1; echo "exit=${PIPESTATUS[0]}"

# 3. Suppress the generated code only, with a reason and an expiry date
cat >> .qgate.yaml <<'EOF'
suppressions:
  - { rule: "semgrep:sql-*", paths: ["gen/**"], reason: "generated by sqlc; fixed upstream", expires: 2999-12-31 }
EOF
echo "== 3"; /tmp/qgate run --base $BASE | head -1; echo "exit=${PIPESTATUS[0]}"
jq -c '.findings[] | {path: .location.path, status, status_note}' qgate-report.json

# 4. Suppress everything instead: the gate passes and security scores 100
sed -i.bak 's#paths: \["gen/\*\*"\], ##' .qgate.yaml
echo "== 4"; /tmp/qgate run --base $BASE | head -1; echo "exit=${PIPESTATUS[0]}"
jq -c '.scores.categories.security' qgate-report.json

# 5. Once the suppression expires it stops applying, with a warning
sed -i.bak 's/expires: 2999-12-31/expires: 2020-01-31/' .qgate.yaml
echo "== 5"; /tmp/qgate run --base $BASE | grep -E "Gate outcome|Warning"; echo "exit=${PIPESTATUS[0]}"

# 6. An impossible date is caught before anything runs
sed -i.bak 's/expires: 2020-01-31/expires: 2027-02-30/' .qgate.yaml
echo "== 6"; /tmp/qgate validate; echo "exit=$?"
```

What to point out:

1. **Step 2:** both findings are new and high, so the blocking gate fails (exit 1).
2. **Step 3:** the suppression names a rule glob, a path glob, a reason and an expiry. The generated file's finding is suppressed and carries the reason; `app.go` is untouched, so the gate still fails. Suppressions excuse exactly what they name.
3. **Step 4:** suppressing both, the gate passes and security scores 100: suppressed findings never count.
4. **Step 5:** after its expiry date the suppression stops applying, the gate fails again, and the console says why.
5. **Step 6:** an impossible expiry date is a config error (exit 2) before anything runs.
